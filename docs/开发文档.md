## 1. 技术选型与架构

### 为什么是 CEP 而不是 UXP

Illustrator 2023 的宿主版本号是 **27.x**（不是 23.x——23.x 是 CC 2019）。UXP 在 AI 2023 上不可用，因此选择 **CEP**（HTML 面板 + ExtendScript 宿主脚本）。

manifest 声明 `Host ILST [27.0,99.9]` + `RequiredRuntime CSXS 9.0`，一份扩展同时兼容 2023~2025 及以后。

### 三层结构

```
┌─────────────────────────────────────────────────────────────┐
│  CEP 面板（CEF + Node.js，--mixed-context）                  │
│                                                             │
│  index.html / panel.css                                     │
│      ↓ DOM 事件                                              │
│  main.js        编排：扫描 → 规划 → 翻译 → 回写 → 撤销        │
│      ├── core.js     纯逻辑（无 DOM / 无 Node，可单测）       │
│      ├── http.js     Node 网络层（代理/重定向/重试/节流）      │
│      └── engines.js  引擎适配（Bing/腾讯/有道/Google/…）      │
└─────────────────────────────────────────────────────────────┘
              │ CSInterface.evalScript('TX.xxx("…")')
              │ 返回值恒为 JSON 字符串
┌─────────────────────────────────────────────────────────────┐
│  ExtendScript 宿主（jsx/translator.jsx，ES3）                │
│  TX.scan / TX.apply / TX.undo / TX.ping / …                 │
│      ↓ app.activeDocument                                   │
│  Illustrator 文档（TextFrameItem / Story / Paragraph）       │
└─────────────────────────────────────────────────────────────┘
```

### 为什么网络层必须放 Node

1. CEP 的 CEF 请求受同源策略约束，直接 `fetch` 第三方翻译接口会被 CORS 拦。
2. Node 端可自定义代理（`CONNECT` 隧道），Google 系接口国内必须走代理。
3. Node 端能精确控制超时、重试、并发节流（有道 20 并发只有 4 个成功，必须串行）。

### 一次翻译的完整数据流

```
TX.scan ──► items[{id, paragraphs[{i,text}]}]
   │
   ├─ TXCore.planTasks()     过滤不可译 + 跨对象去重 + 分批
   │        └─► unique[{hash,text,chars,refs}]  +  batches
   │
   ├─ TXEngines.translateBatch(engine, unique, ctx)
   │        └─► map{hash: 译文}
   │
   ├─ TXCore.mergeResults(plan, map)   → updates{itemId:[{i,text}]}
   │
   └─ TX.apply({mode, overflow, items}) ──► 逐段/整框回写 + 溢出处理
```

**去重是核心优化**：10 个按钮都写「Save as」只请求 1 次，译文复用。

## 3. 运行机制：CEP 是怎么把这套东西跑起来的

### 3.1 加载流程

1. Illustrator 启动时扫描 CEP 扩展目录（用户级 `%APPDATA%\Adobe\CEP\extensions`，或共享目录）。
2. 读 `CSXS/manifest.xml`：
   - `MainPath` → `./panel/index.html`（面板页面）
   - `ScriptPath` → `./jsx/translator.jsx`（**自动注入宿主 ExtendScript 引擎**，全局 `TX` 由此而来）
   - `CEFCommandLine` → `--enable-nodejs --mixed-context`（Node 可用）
3. 未签名的扩展要求 `HKCU\Software\Adobe\CSXS.<n>\PlayerDebugMode = 1`（n = 9~12），否则扩展**不出现在菜单里**。

### 3.2 Node 模块怎么被面板加载

`main.js` 里的 `loadNodeModules()`：

```js
var rawPath = cs.getSystemPath(SystemPath.EXTENSION);  // 注意：这是 URL 形式！
var extPath = toLocalPath(rawPath);                    // file:///C:/… → C:/…
TXHttp = req(extPath + '/panel/js/http.js');           // 用 Node 的 require
TXEngines = req(extPath + '/panel/js/engines.js');
```

- **`getSystemPath` 返回的是 `file:///C:/…` 形式的 URL，不是文件路径**，直接喂给 `require` 会报
  `Cannot find module 'file:///…'`。必须先经 `toLocalPath()` 还原（详见 [14.11](#1411-getsystempath-返回的是-url不是文件路径)）。
- `require` 取自 `window.require`（`--mixed-context` 下页面上下文里就有）或 `window.cep_node.require`。
- `loadNodeModules()` 会依次尝试「扩展根目录 → 上两级目录」，全部失败才报错，并把原始路径值与已尝试路径写入面板日志。
- `engines.js` 内部用相对路径 `require('./http.js')`，Node 按文件自身目录解析，正常。
- `core.js` 同时被两种方式加载：`<script>` 标签（挂到 `window.TXCore`）+ Node `require`。**因此它必须两种导出都做**，见 [14.6](#146-cep-面板里-module-和-window-同时存在)。

### 3.3 ScriptPath 脚本的限制

`translator.jsx` 由 CEP 注入，**不是**用 `app.doScript` 跑的，所以：

- 不能用 `#target` / `#include`（预处理器不生效）
- 必须是 ES3 语法（无 `let/const/=>/模板字符串`）
- 没有 `JSON`（ExtendScript 不提供），所以文件内自带 `TXJSON` polyfill

## 4. 通信协议：面板 ↔ ExtendScript

### 4.1 调用形式

```js
// main.js
function callHost(method, arg, cb) {
  var script = 'TX.' + method + '(' + jsLiteral(arg === undefined ? '' : JSON.stringify(arg)) + ')';
  cs.evalScript(script, function (raw) { cb(JSON.parse(raw || 'null')); });
}
```

- 参数以 **JSON 字符串** 传入（ExtendScript 侧 `TXJSON.parse`）。
- 返回值恒为 **JSON 字符串**，且永远带 `ok` 字段：`{ok:true, …}` / `{ok:false, error:"…"}`。
- `TX.ping("")` 这类空参调用统一传空字符串，宿主侧 `TXJSON.parse('')` 返回 `null`，代码用 `|| '{}'` 兜底。

### 4.2 字符串字面量转义（重要）

`jsLiteral()` 用 `JSON.stringify` 生成 JS 字符串字面量，并额外转义 **U+2028 / U+2029**：

```js
function jsLiteral(str) {
  return JSON.stringify(String(str))
    .replace(/\u2028/g, '\\u2028')
    .replace(/\u2029/g, '\\u2029');
}
```

原因：ES3 把 U+2028 当作行终止符，而 `JSON.stringify` 不会转义它。文本里一旦出现（从 PDF 粘贴的文字很常见），`evalScript` 会直接语法报错。

### 4.3 状态驻留

ExtendScript 引擎在宿主进程内**长期存活**，`translator.jsx` 里的模块级变量（`registry` / `undoStack` / `counter`）跨 `evalScript` 调用保留。这是 `scan` 和 `apply` 能靠 `id` 对接的基础。

代价：文档切换、对象删除后 `id` 会失效——`apply` 里对每个 id 做 `item.parent` 存活校验，失效就返回「对象已失效，请重新扫描」。

## 5. 宿主脚本 API（TX）

文件：`com.dsh.aitranslator/jsx/translator.jsx`
全局对象：`TX`，所有方法返回 JSON 字符串。

### 5.1 `TX.ping()`

环境自检。

```json
{
  "ok": true,
  "version": "1.0.0",
  "app": { "name": "Adobe Illustrator", "version": "29.8.1", "locale": "zh_CN" },
  "docCount": 1,
  "doc": { "name": "未命名-1", "path": "", "textFrames": 4 },
  "caps": { "hasOverflowsProp": false, "hasUuid": true, "hasStories": true }
}
```

`caps.hasOverflowsProp` 用来确认宿主版本是否提供 `overflows` 属性（实测 AI 2025 为 `false`）。

### 5.2 `TX.scan(optionsJson)`

**入参**

```json
{ "scope": "document | selection | artboard | layer", "includeLocked": false }
```

> `includeHidden` 在 UI 中未暴露，代码里读的是 `opts.includeHidden`，默认 `false`。
> 注意 `skipped.locked` 同时统计「锁定」和「隐藏」两类（两者共用同一个计数器）。

**出参**

```json
{
  "ok": true,
  "docName": "未命名-1",
  "scope": "document",
  "frameCount": 6,
  "itemCount": 4,
  "skipped": { "empty": 0, "locked": 0, "duplicateStory": 2 },
  "items": [
    {
      "id": "itm1",
      "kind": "point | area | path | onpath | unknown",
      "storyScope": "frame | frames | story",
      "frameCount": 1,
      "chars": 42,
      "paragraphCount": 3,
      "paragraphs": [{ "i": 0, "text": "Save as" }],
      "locked": false,
      "hidden": false,
      "layerName": "图层 1",
      "name": "",
      "bounds": [0, 0, 0, 0],
      "overflow": false
    }
  ]
}
```

**实现要点**

| 步骤 | 做法 | 原因 |
|---|---|---|
| 收集对象 | 按 scope 取根集合 → 递归 `groupItems` / `compoundPathItems` | `document.pageItems` 对组内对象的包含关系在版本间不一致 |
| 去重 | 优先用 `item.uuid` 建 map，无 uuid 时退回数组 identity | 避免组内对象被枚举两次 |
| 联排识别 | `storyRoot()` 沿 `previousFrame` 回溯；`storyInfo()` 沿 `nextFrame` 前进 | 见 [14](#14-真机踩坑清单反直觉务必先看)：未联排时 `nextFrame` 返回自身 |
| 故事拼接 | `collectStoryParagraphs()` 把各框段落按顺序拼成全局段号，同时产出 `paraMap[全局段号] = {frameIndex, localIndex}` | 各框 `contents` 只返回自己那一段 |
| 段落文本 | 去掉尾部 `\r`（`replace(/[\r\n]+$/, '')`） | 段落对象自带段落符 |
| 溢出 | `isOverflowing()` | 见 5.5 |

### 5.3 `TX.apply(payloadJson)`

**入参**

```json
{
  "mode": "paragraph | frame",
  "overflow": { "policy": "expand | shrink | report | none", "maxGrow": 3.0, "minScale": 0.6 },
  "items": [
    { "id": "itm1", "paragraphs": [{ "i": 0, "text": "另存为" }] },
    { "id": "itm2", "frameText": "整框替换文本" }
  ]
}
```

- `mode: "paragraph"` 用 `paragraphs`；`mode: "frame"` 用 `frameText`。
- `paragraphs[].i` 是 **scan 返回的全局段号**，不是框内序号。

**出参**

```json
{
  "ok": true,
  "applied": 12,
  "errorCount": 0,
  "canUndo": true,
  "results": [
    {
      "id": "itm1", "ok": true, "applied": 2, "errors": [],
      "overflowBefore": false, "overflowAfter": false,
      "overflowFix": { "policy": "expand", "tried": 0, "resized": false, "scaled": false, "stillOverflow": false }
    }
  ]
}
```

**回写顺序（关键不变量）**

1. 快照（逐框记录 contents / 宽高 / 字号）→ 压入 `undoStack`（最多 30 步）
2. `applyStoryParagraphs()`：把全局段号映射回 `{frameIndex, localIndex}`，按 **frameIndex 倒序** 逐框处理
3. 框内段落按 **localIndex 倒序** 替换

为什么都倒序：译文长度变化会让文字在框之间回流。**文本只会向后流**，先改后面的框，前面框的段号才不会被冲乱。

**属性快照**：`snapshotCharAttrs()` 记录 size / textFont / fillColor / tracking / horizontalScale / verticalScale / baselineShift，替换后 `restoreCharAttrs()` 写回。这是「保留格式」的核心。

### 5.4 `TX.undo()`

按 `undoStack` 弹出最近一次快照，**逐框倒序**还原 contents、宽高、字号。

```json
{ "ok": true, "restored": 4, "errors": [], "canUndo": false }
```

注意：撤销还原的是 `contents`（框局部），不是整段故事——因为 setter 也是框局部的。

### 5.5 溢出检测：`isOverflowing(item)`

```js
// 1) 官方属性优先（AI 2025 实测不存在，恒为 undefined）
if (typeof item.overflows === 'boolean') return item.overflows;
// 2) 兜底：可见行字符总数 + 行数 < 全文长度
var total = item.textRange.length;
var visible = Σ lines[i].contents.length;
return (visible + lines.length) < total;
```

原理：溢出时隐藏行**不计入** `lines`（实测 60×30 框放 82 字，`lines.length = 2`）。
正常时 `visible + (行数-1) ≈ total`，所以判据带 1 行的容差。

已知边界：大量空行的排版可能误判，此时把策略设为「只标记」即可。

### 5.6 `TX.selectItem(id)` / `TX.readItem(id)`

```js
TX.selectItem(id)  → {ok:true, id} | {ok:false, error}
TX.readItem(id)    → {ok:true, id, contents, chars, paragraphs:[{i,text}], overflow}
```

`selectItem` 用于列表点击定位；`readItem` 用于回读校验（E2E 测试大量使用）。

## 6. 纯逻辑层 API（TXCore）

文件：`panel/js/core.js` · 无副作用、无 DOM、无 Node，可直接在 Node 里跑。

| 函数 | 签名 | 说明 |
|---|---|---|
| `detectScript` | `(text) → 'cjk'\|'latin'\|'cyrillic'\|'mixed'\|'none'` | 字符集判定 |
| `isCjkLang` | `(lang) → bool` | `/^(zh\|ja\|ko)/i` |
| `splitParagraphs` | `(text) → string[]` | 兼容 `\r` `\n` `\r\n` |
| `joinParagraphs` | `(list, sep='\r') → string` | |
| `flatten` | `(text) → string` | 多行压单行、合并空白，送引擎前必做 |
| `checkTranslatable` | `(text, opts) → {ok, reason}` | 见下表 |
| `applyGlossary` | `(text, pairs, phase) → string` | `phase='before'` 原文替换；`'after'` 预留纠偏 |
| `planTasks` | `(items, opts) → {tasks, unique, skipped, batches, stats}` | 过滤 + 去重 + 分批 |
| `simpleHash` | `(str) → string` | djb2 + 长度，用于去重 key |
| `cleanTranslation` | `(text) → string` | 去代码块/前缀/外层引号，压换行 |
| `parseTranslationArray` | `(raw, expected) → string[]` | 解析 LLM 输出，**数量不符即抛错** |
| `mergeResults` | `(plan, map) → {itemId:[{i,text}]}` | 译文回填到段落 |
| `estimateRatio` | `(src,dst) → number` | 长度比 |
| `transformCase` | `(text, mode) → string` | `mode`：`keep`/`upper`/`lower`/`title`；中文等无大小写字符原样保留 |
| `titleCase` | `(text) → string` | 单词首字母大写，其余字母**不动**（`OPEN FILES` 不会被改成 `Open Files`） |
| `caseChanges` | `(text, mode) → bool` | 该模式下是否真的会变（决定要不要回写） |
| `caseTransformAllowed` | `(reason) → bool` | 被跳过的段落是否允许改大小写；`url-email` / `placeholder` 返回 false |
| `CASE_MODES` | `['keep','upper','lower','title']` | 合法模式列表 |
| `buildLlmPrompt` | `(texts, opts) → string` | 构造大模型提示词 |

### `checkTranslatable` 的跳过原因

| reason | 触发条件 |
|---|---|
| `empty` | 压平后为空 |
| `too-short` | 短于 `minChars`（默认 1） |
| `no-letter` | 纯数字/符号，或一个字母都没有 |
| `url-email` | 整条是 URL 或邮箱 |
| `placeholder` | 形如 `{x}` `[x]` `<x>` `%x%` `#x#` |
| `already-target-lang` | 目标是 CJK 语言且原文已是 CJK（可关） |
| `same-script` | 目标非 CJK、源语言为 auto、原文是拉丁文（可关） |

### `planTasks` 返回结构

```js
{
  tasks:   [{itemId, paraIndex, hash}],              // 每个待翻译段落一条
  unique:  [{hash, text, chars, refs:[{itemId,paraIndex}]}],  // 去重后的唯一文本
  skipped: [{itemId, paraIndex, text, reason}],
  batches: [{texts:[…], chars, oversized?}],         // 按 maxItems/maxChars 切好
  stats:   {paragraphCount, uniqueCount, skippedCount, batchCount, savedByDedupe}
}
```

超长文本（`chars > maxChars`）单独成批并标 `oversized: true`。

| `url` / `method` / `headers` / `body` | — | `body` 支持 string / Buffer / 对象（自动 JSON 序列化） |
| `timeout` | 20000 | |
| `retries` | 1 | **每条通道**的重试次数 |
| `retryDelay` | 600 | 退避基数（带随机抖动） |
| `proxy` | — | `http://127.0.0.1:7897` |
| `autoProxy` | — | 无 `proxy` 时的备选通道 |
| `noProxyFallback` | false | 禁止回退直连 |
| `followRedirect` | true | |
| `maxRedirects` | 5 | |

### 返回值

```js
{ status, headers, text, ms, finalUrl, cookies, usedProxy, channel }
```

`cookies` 是**整条重定向链**收集到的 Cookie（Bing 依赖这个跨 `www→cn` 域传递）。

### 通道回退策略（关键设计）

```
配置了 proxy  → 先试 proxy，失败再试直连
没配置 proxy  → 先直连，失败再试 autoProxy
```

这样既能翻墙用 Google，又不会因为代理不通而拖垮国内接口。错误信息按通道拼接（`代理 http://… 超时 ｜ 直连 ECONNRESET`），便于定位。

`isRetryable()` 判定：网络类错误（`ECONNRESET/ETIMEDOUT/EAI_AGAIN/…`、超时、TLS 断开）+ HTTP 429/5xx。

## 8. 引擎层 API（TXEngines）

文件：`panel/js/engines.js` · CommonJS。

### 8.1 引擎契约

```js
{
  id: 'tencent',
  name: '腾讯交互翻译',
  free: true,            // 是否免 Key
  needsKey: false,
  maxItems: 40,          // 单次请求最大条数
  maxChars: 4000,        // 单次请求最大字符数
  note: '……',            // 面板提示
  async translate(texts, ctx) → string[]   // 长度必须与 texts 一致，否则抛错
}
```

`translate` **抛错即视为该引擎失败**，`translateBatch` 会按顺序降级到下一个。

### 8.2 导出

| 导出 | 说明 |
|---|---|
| `ENGINES` | `{id: engine}` |
| `LANGS` | `LANGS[lang][engineId] → 引擎侧语言码` |
| `AUTO_ORDER` | `['tencent','bing','youdao','google','mymemory']` |
| `engineList()` | 面板下拉用的精简数组 |
| `langOf(engineId, lang)` | 语言码转换，找不到时原样返回 |
| `batchesFor(engineId, unique, opts)` | 按引擎上限切批 |
| `translateBatch(engineId, unique, ctx)` | **主入口**，见下 |
| `diagnose(engineId, ctx)` | 单条短文本探活，供「网络诊断」用 |

### 8.3 `ctx` 字段

| 字段 | 说明 |
|---|---|
| `targetLang` / `sourceLang` | `zh-CN` / `auto` 等 |
| `targetLangLabel` | 给大模型用的中文语言名（「简体中文」） |
| `proxy` / `autoProxy` | 传给 `http.request` |
| `apiKey` / `baseUrl` / `model` / `preset` | 需 Key 引擎用 |
| `glossary` | `[{from, to}]` |
| `mymemoryEmail` | MyMemory 提高额度的邮箱 |
| `llmTimeout` | 大模型超时，默认 120s |
| `log(msg)` | 回调写面板日志 |
| `onProgress(done, total, engine)` | 每批完成回调 |

### 8.4 `translateBatch` 返回

```js
{ engine: 'tencent', map: {hash: 译文}, tried: [{engine, ok, ms, error?}], failed: [] }
```

- `engine === 'auto'` 时按 `AUTO_ORDER` 依次尝试，全部失败抛 `Error`（带 `.tried`）。
- 每批译文数量必须与请求一致，否则抛错换引擎——**宁可失败也不允许错位回写**。
- 每批完成后回调 `onProgress`。

### 8.5 各引擎实现要点

| 引擎 | 关键实现 |
|---|---|
| **tencent** | 单次请求带 `text_list` 数组，一次最多 40 条；`header.ret_code !== 'succ'` 视为失败 |
| **bing** | 两段式：GET `cn.bing.com/translator` 拿 `params_AbusePreventionHelper` + `IG`/`IID` + Cookie，再 POST `ttranslatev3`。会话缓存 6 分钟、用满 8 次刷新。**空响应 = 限流**：同会话重试 1 次，连续 3 次空则冷却 5 分钟并抛错触发降级 |
| **youdao** | 一条一请求，`createSerialQueue(160)` 严格串行（20 并发实测只有 4 成功） |
| **google** | `translate_a/single?client=gtx`，并发 3；国内必须代理 |
| **mymemory** | 一条一请求，串行 200ms 间隔；`quotaFinished` 直接抛错 |
| **deepl** | 重复 `text` 参数批量提交，`Authorization: DeepL-Auth-Key` |
| **openai** | 兼容 OpenAI 协议，一次提交 JSON 数组 + 提示词，用 `core.parseTranslationArray` 严格解析；预设 DeepSeek / 智谱 GLM-4-Flash / 硅基流动 / Ollama / OpenAI |

### 9.6 输出大小写的两条路径

`doTranslate` 里大小写有**两个入口**，缺一不可：

```js
// 路径 A：译文套用大小写（有翻译发生时）
if (caseMode !== 'keep') {
  Object.keys(result.map).forEach(h => result.map[h] = TXCore.transformCase(result.map[h], caseMode));
}

// 路径 B：被跳过的段落也要改大小写（没有翻译发生，或该段被规则跳过）
plan.skipped.forEach(s => {
  if (!TXCore.caseTransformAllowed(s.reason)) return;      // URL / 邮箱 / 占位符不动
  var t = TXCore.transformCase(s.text, caseMode);
  if (t !== s.text && t.replace(/\s/g, '') !== '') caseOnly.push({ itemId: s.itemId, paraIndex: s.paraIndex, text: t });
});
```

**为什么必须有路径 B**：目标语言选英语时，画布上已是英文的段落会命中 `same-script` 规则被跳过。
如果只做路径 A，这些段落永远不会被转成大写——而这个恰恰是「输出大写英文」最常见的场景。

配套逻辑：
- `plan.unique` 为空但 `caseOnly` 非空时，**跳过网络请求**直接进入回写（状态栏显示「完成：仅调整大小写 N 段」）。
- `caseOnly` 的段落合并进 `updates` 一起提交给 `TX.apply`，与译文段落在同一个 payload 里。
- `payloadItems` 为空时提前返回，不发无意义的一次 `TX.apply`。

> 新增「输出样式」类功能（比如全角/半角转换）时，照抄这个双入口结构即可。

## 10. 数据契约与不变量

1. **段号语义**：面板侧一律使用 **scan 返回的全局段号**；`paraMap` 是宿主内部的翻译表，不暴露给面板。
2. **空段落不写**：`normalizeText('')` 后为空的段落直接跳过，避免破坏框边界空段。
3. **译文不含换行**：`cleanTranslation` + `normalizeText` 双重压平，防止破坏段落结构。
4. **回写幂等性**：同一份 payload 重复 apply 结果一致（因为按段号定位，不依赖位置）。
5. **失败即不写**：任何一段抛错只记录在 `results[].errors`，不影响其他段；整体 `ok` 仍为 true。
6. **id 生命周期**：一次 `scan` 生成的 id 只保证在当前文档、当前引擎会话内有效。
7. **引擎译文数量必须一致**：数量不符抛错换引擎，禁止错位回写。
8. **大小写只作用于最终文本**：先翻译、后转大小写；被跳过的段落若在变换后与原值不同也要写回，但 URL / 邮箱 / 占位符永不参与变换。

## 11. 扩展开发指南

### 11.1 新增一个翻译引擎（最常见的需求）

**第一步**：在 `engines.js` 写适配函数，签名 `(texts, ctx) => Promise<string[]>`。

```js
async function myEngineTranslate(texts, ctx) {
  var res = await http.request({
    url: 'https://api.example.com/translate',
    method: 'POST',
    headers: { 'content-type': 'application/json', authorization: 'Bearer ' + ctx.apiKey },
    body: { texts: texts, from: ctx.sourceLang, to: langOf('myengine', ctx.targetLang) },
    proxy: ctx.proxy,
    timeout: 30000,
  });
  need(res);                                  // 非 2xx 直接抛错
  var data = JSON.parse(res.text);
  if (!data || !data.results) throw new Error('返回结构异常');
  if (data.results.length !== texts.length) throw new Error('译文数量不匹配');
  return data.results;
}
```

**第二步**：在 `LANGS` 里补语言码：

```js
'zh-CN': { …, myengine: 'zh' },
```

**第三步**：注册到 `ENGINES`：

```js
myengine: {
  id: 'myengine', name: '我的引擎', free: false, needsKey: true,
  maxItems: 20, maxChars: 2000, note: '需要 API Key',
  translate: myEngineTranslate,
},
```

**第四步**：如果是免费的，加进 `AUTO_ORDER`（顺序即降级优先级）。

**第五步**：在 `tools/test-core.mjs` 的联网测试列表里加 `'myengine'`，跑 `node tools/test-core.mjs --network --engine=myengine`。

面板下拉会自动出现新引擎（`engineList()` 动态生成），无需改 HTML。

### 11.2 新增语言

1. `LANGS` 每个引擎行补该语言的代码。
2. `main.js` 的 `LANG_OPTIONS` 加一项 `['xx', '语言名']`。
3. 若目标是 CJK 语言，`core.isCjkLang` 的正则要能匹配。

### 11.3 新增回写模式

1. `translator.jsx` 的 `apply()` 里加分支（`mode === 'xxx'`）。
2. 面板 `index.html` 的 `#writeMode` 加 `<option>`。
3. `e2e-full.jsx` 加断言。

### 11.4 新增溢出策略

在 `fixOverflow(item, policy, opts)` 里加分支，返回 `{policy, tried, resized, scaled, stillOverflow}`。注意：
- 每一步都要重新调 `isOverflowing()` 判断
- 放弃时**必须还原**初始宽高/字号

### 11.5 改 UI

`index.html` 加控件 → `main.js` 的 `SETTING_KEYS` 加 key（自动持久化）→ `bindEvents()` 绑事件 → `tools/test-panel.mjs` 加断言。jsdom 测试会真实执行你的 DOM 代码，能挡住 id 写错、初始化异常这类问题。

## 14. 真机踩坑清单（反直觉，务必先看）

这些都是**实测推翻想当然**的结论，改动相关代码前先读：

### 14.1 `textFrame.overflows` 不存在

AI 2025 上 `typeof item.overflows === 'undefined'`。官方脚本参考的 `TextFrameItem` 属性表里也没有它（有 `contents/kind/nextFrame/previousFrame/paragraphs/textRange/story/…`，就是没有 `overflows`）。
→ 必须用行字符数兜底（5.5 节）。

### 14.2 联排框的 `contents` 是「框局部」的

2 框故事：`f1.contents.length = 33`、`f2.contents.length = 638`、`f1.story.textRange.length = 671`。
→ 只读根框会漏掉后面所有框；必须拼接各框并记录 `paraMap`。

### 14.3 `contents` 的 setter 同样是框局部的

给根框写整段故事，**后续框的旧内容会残留在后面**。
→ 撤销必须逐框倒序还原，不能只写根框（第一版就是这么错的，E2E 抓到「itm2 段7/8/9 未还原」）。

### 14.4 `nextFrame` 在未联排时返回自己

- 未联排的区域文本：`nextFrame === frame`（自环）、`previousFrame === null`
- 联排末框：`nextFrame === frame`
- 点文本：访问 `nextFrame` **直接抛异常**（「属性不可用于此类型文本框」）

→ 遍历必须「自环即停 + try/catch」，否则绕成死循环（第一版 `frameCount` 跑成 500）。

### 14.5 Bing 的「空 200」是限流，不是会话失效

埋点实验（`tools/debug-bing3.mjs`）：约 8 条之后，Bing 对每个请求都返回 `HTTP 200` + **空 body**，换新会话也没用，最长连续 20 次空。
→ 处理策略：同会话重试 1 次（偶发空能救回）；连续 3 次空则冷却 5 分钟 + 抛错，让 `auto` 降级到有道/腾讯。**不要**一遇到空就换会话（那是第一版的死循环写法）。

### 14.6 CEP 面板里 `module` 和 `window` 同时存在

`core.js` 原本写成「有 `module` 就只走 CommonJS 导出」，结果面板里 `window.TXCore` 是 `undefined`，点「翻译」直接崩。
→ UMD 必须**两种导出都做**（`test-panel.mjs` 抓到的）。

### 14.7 `document.pageItems` 对组内对象的包含关系不可靠

→ 递归 `groupItems` 收集 + 按 `uuid` 去重。

### 14.8 PowerShell 5.1 读无 BOM 的 UTF-8 脚本会乱码

`tools/*.ps1` 里的中文注释会导致「字符串缺少终止符」这类语法错误。
→ **所有 .ps1 必须存成 UTF-8 with BOM**（仓库里的已经处理过，新增脚本注意）。

### 14.9 ExtendScript 没有 JSON

`translator.jsx` 自带 `TXJSON`；`e2e-full.jsx` 里要用 `TX._json.parse`。

### 14.10 U+2028 / U+2029 会让 `evalScript` 语法报错

见 4.2，`jsLiteral` 已处理。

### 14.11 `getSystemPath()` 返回的是 URL，不是文件路径

真机返回值形如：

```
file:///C:/Users/<用户名>/AppData/Roaming/Adobe/CEP/extensions/com.dsh.aitranslator
```

而且路径里的非 ASCII 会被**百分号编码**（`file:///C:/…/AI%E7%BF%BB%E8%AF%91%E6%8F%92%E4%BB%B6/…`）。

Node 的 `require()` **不认 `file://` 前缀**（那是 `import()` 的语法），于是启动时直接报：

```
网络层加载失败：Cannot find module 'file:///C:/…/panel/js/http.js'
Require stack: - /C:/…/panel/index.html
```

→ `CSInterface.getSystemPath()` 必须做三步还原：`decodeURI` → 去掉 `file:///` / `file://` → 去掉 `/C:/` 形式的前导斜杠。

这正是官方 CSInterface 里 `path.replace("file:///", "")` 那句的作用，写精简版时最容易漏掉。
`main.js` 的 `toLocalPath()` / `loadNodeModules()` 做了第二层兜底：多候选目录逐个尝试，失败时把「原始路径值 + 已尝试路径列表」写进面板日志，避免只有一个 `Cannot find module` 让人无从下手。

`tools/test-panel.mjs` 的假宿主现在返回真实的 `file:///` + 百分号编码形式，专门回归这个问题（旧代码会在这条断言上直接失败）。

## 15. 编码规范

| 位置 | 规范 |
|---|---|
| `jsx/translator.jsx` | **ES3**：`var`、无箭头函数、无模板字符串、无 `JSON`、不用 `#include` |
| `panel/js/*.js` | 面板要兼容 CEP 内置的旧 Chromium，同样避免过新语法；`core.js` 必须 UMD 双导出 |
| 网络请求 | 一律走 `TXHttp.request`，不要直接 `https.request`（否则失去代理回退与重试） |
| 新增引擎 | 必须实现数量校验；抛错即降级；尊重 `ctx.proxy` |
| 错误信息 | 面向用户写中文，包含可操作信息（哪个引擎、什么原因） |
| 日志 | 面板 `log(msg, 'ok'\|'warn'\|'err')`；引擎失败经 `ctx.log` 上报 |
| .ps1 | UTF-8 **with BOM**；先 `Parser::ParseFile` 校验语法 |
| 提交前 | `node tools/test-core.mjs && node tools/test-panel.mjs`，改动宿主脚本再加 `tools/e2e/run-e2e.ps1` |
